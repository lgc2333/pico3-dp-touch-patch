# 04.g · 手和模型的解耦：握把位姿（2026-10-18）

> 总览：[04 · PC 端 OpenVR 驱动](04-driver.md)。
> 状态：**已定稿，实机验证**。
> 由来：[04.e](04_e-driver-apprun-offset.md) 修掉「游戏里手柄偏 4.28cm / 10.29°」之后，暴露出另一个问题——VRChat / The Lab 里虚拟手不在手心、手臂伸不直。本篇只记这一条；这条偏移的根因与修法见 04.e，排查与证伪过程见 [04.f](04_f-driver-offset-investigation.md)。（下文 `device pose` = 驱动发布给所有消费者的手柄位姿；`/pose/raw` 就是它。）

## 现象与判据

- 应用里：虚拟手（VRChat 的 avatar 手、The Lab 的机器人手）落在手柄柄尾 / 下方，手柄模型浮在手心外；手腕处的 IK（反解手臂的逆运动学）显得短一截（「手伸不直」）。
- SteamVR 面板：模型和实物对位正常（说明 device pose 本身没漂）。
- `apprun` 补丁（见 [04.e](04_e-driver-apprun-offset.md)）前后都在；补完之后反而更明显——那 4.28cm 正好把手往外推了一点，把问题盖住了一半。

## 根因：手和模型吃的是同一个 device pose

- **VRChat 的手 = legacy device pose**（不走 SteamVR Input 动作绑定、直接读设备位姿的老路径）：`bindings_oculus_touch.json`（VRChat 的 SteamVR 绑定）里 pose 绑 `/user/hand/*/pose/raw`（raw = device pose），但 `vrclient_VRChat.txt` 里记着 `app appears to not be using SteamVR Input`；改绑 `handgrip`、加 SteamVR `pose_offset` 都没让手相对模型动（`device_offsets` 则是把两者一起移，相对位置不变）⇒ 手不是从 SteamVR Input 的 pose 来的。
- **手柄模型 = 同一个 device pose + OBJ 顶点**：`component_local.origin` 只影响 pose / 挂接点，不参与网格摆放（实测：把 `body` 的 `component_local.origin.z` 从 0.097 改成 0 并重启 SteamVR，渲染网格一动不动）。
- 驱动把 device pose 报在**跟踪环附近**；握把在柄身 `+Z` 约 9.7cm 处。手按 device pose 抓握，就落在环附近，比握把低 / 前一截。

## 试过、无效（别再走）

| 试法                                                                 | 结果                                                          |
| -------------------------------------------------------------------- | ------------------------------------------------------------- |
| `component_local.origin`（`body.component_local.origin.z: 0.097→0`） | 渲染网格不动 ⇒ 只影响 pose / 挂接点，不能移模型               |
| VRChat 改绑 `pose/handgrip`                                          | 手动没动（app 不吃这条 pose）                                 |
| SteamVR `pose_offset`（创意工坊绑定的 pose 里加 `pose_offset`）      | 手动没动；`vrserver` 无解析报错                               |
| `device_offsets` / 「原始设备偏移」                                  | 手和游戏自己画的手柄一起移，相对位置不变                      |
| 补 `openxr_grip`                                                     | app 绑的是 `pose/raw`，看不到它                               |
| 只改 `[controller]`、不补顶点                                        | 手对了，模型跟着偏 4.28 cm（两环相碰时模型会互相穿插）        |
| 只补顶点、不改 JSON 的 `motion`                                      | 手和模型位置都对了，但扳机等活动部件绕旧支点转（支点偏 ~4cm） |

⇒ app 改不了、pose 一改就两者一起动，**网格是唯一能单独动模型的旋钮**。

## 定稿：成对改位姿 + 顶点

**位姿**：`RVRPlugin.ini` 的 `[controller]`（`sub_180032AE0` 每 5 ms 读一次；`sub_180018340` 按 `q' = q·q_off` 旋转、`p' = p + R(q')·t` 平移）。

**顶点**：`resources\rendermodels\pico_neo3_{left,right}controller\*.obj` 用 `v' = Rz(-roll)·Ry(-yaw)·v - t` 反向补偿（旋转先做、再减 `t`）。

**活动部件**：两份同名 JSON 里 `motion` 块的 `pivot` / `center` 是**点**（`p' = R·p - t`），`axis` / `press_translate` 是**向量**（`v' = R·v`），必须跟顶点一起变。它们和顶点同处模型空间（证据：右手 `trigger` 的 `component_local.origin.z = 0.051`，但左右扳机网格 bbox 完全镜像、`motion.pivot` 也相同 ⇒ 网格不吃 `component_local`）。只改顶点时扳机仍绕**旧**支点转，扣扳机整块像被甩出去。

### 数值与来源

- 平移 `t`：左 `(+0.0099, +0.0115, -0.0401)`、右 `(-0.0099, +0.0115, -0.0401)`——就是 [04.f](04_f-driver-offset-investigation.md) 的「改判」里量到的 4.28 cm 在自身系的分解。
- 旋转：绕自身轴 `≈(0,-0.096,+0.994)` 的 10.29°；ini 写成左 `yaw=-0.99 / roll=+10.23`、右 `yaw=+0.99 / roll=-10.23`（pitch 0）。
- 左右手的 `t.x` 符号相反（模型在 x 上镜像）；顶点旋转先做、再减 `t`。
- 实机：VRChat / The Lab / Alyx / SteamVR 面板四组都正常；两环相碰不再互相穿插。

### 扳机支点（2026-10-19 补）

- 现象：补丁后虚拟手 / 模型位置都对了，但扣扳机时扳机绕错的支点转（整块往旁边甩）。
- 根因：只改了 OBJ 顶点，`motion.pivot` 还停在旧位置（`trigger` 是 `(0, 0.012, 0.012)`），顶点却整体挪了 ~4cm ⇒ 支点相对网格偏了 ~4cm。
- 定稿：`motion` 的 `pivot/center/axis/press_translate` 用与顶点同一套 `R` / `t` 变换；左扳机 `pivot → (-0.007565, 0.000272, 0.052098)`、`axis → (0.983956, -0.177574, -0.017278)`，右手为 x 镜像。`motion.rotate_xyz` 现有模型全 0；出现非 0 直接中止（没实现它的补偿）。
- 验证（离线）：变换后支点到扳机网格的最近距离与变换前一致（差 < 1e-6）；两份 JSON 的厂商 sha256 卡在脚本里、整份从 `.orig` 重算（含 `tip` 笔误），重复跑无写入。**实机待确认**。

### 摇杆：支点、转轴、倾角（2026-10-20 定稿）

- 归属：`center` / `rotate_xyz` 与顶点同属握把补丁（不补就是回归）；厂商另有两处老问题——支点离轴 ~25 mm、参数按另一个轴向写。
- 现象：推杆时帽整根滑开；只挪支点、不改转轴时变成「左右几乎不动、按下侧滑」。
- 根因（vrserver `RendermodelManager`，`sub_1401E0080` 的 case 5 与 `sub_1401E27D0`）：
  - `center` 是点支点：`A = c + S·press + Q(v − c)`，`Q = S·Rz(θx)·Rx(θy)·Sᵀ`，`S = rotate_xyz`；`pivot` 只用于 `rotate` 型部件。
  - 两个转轴是**代码写死的模型 X 与 Z**（X 输入给 `Rz`、Y 输入给 `Rx`），JSON 里的 `axis` 不参与。
  - 厂商按「摇杆沿 **Y** 轴」写这套参数（`press_translate = (0,-0.0025,0)` 是按沿轴写的；符号在实机上是往外弹，见下）；网格里摇杆沿实测按键平面的法向（与 +z 成 66.8°）⇒ X 输入变成绕杆自转，`press` 变成侧滑。厂商靠偏心支点的力臂把它硬拧成平移，才显得「会动」。
- 几何（`.orig` 网格；左右手各自 4 颗按键帽的 PCA 薄轴）：
  - 平面法向：左 `(+0.10979, +0.91278, −0.39342)`、右 `(−0.10987, +0.91302, −0.39285)`；4 颗帽互差 ≤2.4°。
  - 平面位置：左手 `n·p = 13.875 mm`；帽顶露出 7.44 mm、杆底埋入 3.01 mm。
  - 杆轴：方向固定为法向，只拟合两维平移（±2 mm 网格）⇒ 左手拟合点 `(−14.949, 31.237, 23.201) mm`。
  - 杆自身的轴线（帽沿圆心 r 5.81 与底部圆环 r 7.87 的连线）与法向差 **1.07°**：帽心离它 0.04 mm、底环心 0.16 mm。这是低模自身的扰动（4 颗帽法线差 2.4°、机身凹坑轴心离杆轴 0.257 mm）。「支点垂直于按键平面」与「支点沿杆自身轴线」差这 1°，只能二选一；取平面法向。
- 定稿（左右各自从 `.orig` 重算；值见 `patch_driver.ps1` 的 `$handCfgs`）：
  - `center`：杆轴与平面的交点，再沿法线下 **4.0 mm** ⇒ 左 `(−0.0158132, 0.0240547, 0.0262966) m`，右为 x 镜像；再过点变换，JSON 写 `(−0.02074, 0.0149, 0.066666)` / `(0.020738, 0.014908, 0.066657)`。**4.0 mm 是用户按手感选的**；几何参考：杆底在平面下 3.01 mm，支点再低 0.99 mm，悬在底环的开口里。
  - `rotate_xyz`：由**顶点变换之后**的法向 `R·n` 重算 `S`（第二列 = `R·n`，平面内的「上」= **世界 up 在该平面内的投影**，一条转轴严格水平）⇒ 左 `[0, −156.718, 163.333]`、右 `[0, −156.753, −163.329]`。照变换前的法向写，转轴会斜出水平面 0.98°。
  - 手感补偿试过一轮、**已全部撤掉**：按「握柄轴投影」「握把中点 → system 键」这些参照，绕杆轴拧过 1.03 / 1.83 / 2.23 / 2.40 / 3.00 / 6.00°，也反向试过 −3.00°（负方向更顺时针 ⇒ 方向本身没错，但幅度一直对不上）。设备侧轴映射实测是**径向**的（见下条），不会转动倾倒方向 ⇒ 残余更像姿势/手法问题，不是这个角度。用户最终选择回到**几何参考**，不再按手感拧。
  - `press_translate`：写 `(0, +0.0025, 0)`，即厂商原值取反。它活在 `S` 坐标系里；跟点一起做 `R·v` 会让按下变成切向滑 0.44 mm。**符号是实机定的**（2026-10-20）：厂商的 −2.5 在 VR 里是**往外弹**（查看器当时反而画对了）⇒ 以实机为准，写 +2.5 才压进去。
  - `joystick_rotation_x/y`：幅度 12°（厂商是 6.5°，**用户在查看器里按手感选定**）。符号由实机定：X 取 `[−12, 12]` = 推右向右倒；Y 取反 `[12, −12]` = 推上向上倒（两轴同号时实机 y 轴反向，2026-10-20 装后确认）。
  - 4.0 mm 与 12° 都能在 [artifacts/joystick-viewer](artifacts/joystick-viewer/README.md) 的页面上改，再把两支值抄回脚本。
- 复核（离线，按上面的矩阵重算）：
  - `S·ŷ` 与 `R·n` 差 5e−6；`S·x̂` 的 z 分量 = 0（严格水平）；`S·ẑ` = 世界 up 在平面内的投影。
  - 按下：文件里是 `(0, +0.0025, 0)`；按 `c + S·press` 算出来是沿 +`R·n` 2.5 mm，实机看到的却是压进去 —— 该公式的符号约定不是 vrserver 实际的，以实机为准。切向 1e−5 mm（原来 0.44 mm）。
  - JSON 的 `center` 反变换回模型空间，与 4.0 mm 的支点差 < 5e−4 mm。
  - 12° 时帽心沿弧走 2.27 mm（纯旋转，无额外侧滑）；帽沿两侧沿轴差 2.3 mm（−1.4 / +0.9），帽心下沉 0.24 mm。
  - 两份 JSON 整份从 `.orig` 重算，重复跑无写入。**实机待确认**。
- 轴映射实测（2026-10-20，Frida dump `controller_data_t` 的 54 / 55 字节，左右手各 11 276 采样、60 s）：静止 = 128/128（零点精确）；**最小非零输出 1 个计数**（设备侧没有中心死区）；四向满偏都到 ±1.008；边缘半径 1.00–1.01 跟着理想圆（映射是**径向**的，方向角不变）；单轴各自夹在 ±1（推满后横移，另一轴仍变）。⇒ 映射压不了方向，`rotate_xyz` 不必再为「方向偏」而拧；真正的手感死区在下游（SteamVR 绑定 / 游戏自己的死区）。
- 其余活动部件：扳机支点离扳机网格 2.5 mm、轴 `X`（正常合页）；握把键 `pivot (0.005,-0.012,0)` 离网格 64 mm，但轴是 `Y`、只转 2.5° ⇒ 等效于朝柄内平移 3 mm，方向正确，视觉上就是按压 ⇒ 保持原样。

### 代价与注意

- `[controller]` 是**全局**的：所有 app 的 device pose 都挪 4.3 cm；用 `handgrip` / `base` 组件（手柄 JSON 里声明的握把 / 底部挂接点）的 app 会跟着多偏 4 cm（VRChat / Alyx 走 `raw` / 骨架，不受影响）。
- 旋转只用了 `roll≈10.23° + yaw≈0.99°`；要调手掌朝向就改 ini 并**同步重算顶点与 motion 参数**。
- 模型补偿要重启 SteamVR 才重载；ini 基本实时生效。
- 落地：`patch_driver.ps1` 的手柄阶段（`.orig` = 脚本动手前的备份（见 README「还原」）；17 个原始 OBJ 与两份 JSON 的厂商原件 sha256 卡死、从 `.orig` 重算，幂等）。
