# 02 · DP 的 HID 报文协议与抓包

## 设备与端点

头显 USB 复合设备（`VID_2D40` = 11584）：

| PID    | 接口        | 类                    | 用途                               |
| ------ | ----------- | --------------------- | ---------------------------------- |
| `0016` | MI_00       | MEDIA                 | 音频                               |
| `0016` | MI_03       | **HIDClass**          | **64 字节 HID 报文流（本文重点）** |
| `00B5` | MI_00/01    | AndroidUsbDeviceClass | PICO Streaming Interface / ADB     |
| `00B7` | MI_00/01/02 | WPD / Streaming / ADB | 同上（另一种模式）                 |

PC 驱动只用 `PID_0016` 的 HID 接口：`hid_open(0x2d40, 0x16, 0)`，且**只处理恰好 64 字节**的报文。
端点：`0x81`/`0x03` = 等时音频（1920 B），`0x82` = 中断 HID（64 B）。

## 64 字节报文格式

```
[0]   = 0xAA            固定魔数
[1]   = flags           实测 0x54 / 0x05 / 0x00 / 0x55
[2]   = type << 5       type = buf[2] >> 5
[3..] = payload
```

`sub_180025A90` 里 `type = payload[1] >> 5`（payload = `buf[1..63]`，即 type 取自 **`buf[2]`**）：

| type | 处理函数        | 含义                        |
| ---- | --------------- | --------------------------- |
| 0    | `sub_180026E60` | IMU 流（带时间戳）          |
| 1, 2 | `sub_1800274B0` | **左 / 右手柄**（含键值字） |
| 3    | `sub_180027EF0` | 空闲心跳（未串流时 1 Hz）   |
| 4    | 内联            | chaperone（游玩区边界）     |

三条 IMU 流（type0/1/2）串流时各约 330 Hz，合计 ~1000 Hz。

## 头显侧报告体的精确布局（`HidIOListener::hidWrite` 反编译 + 抓包双向确认）

头显把 63 字节报告体交给 `hidWrite`，后者**加上 `0xAA` 前缀**写成 64 字节：

```c
// libpxrstreamingservice.so :: HidIOListener::hidWrite(mutex, data, 63)
LOBYTE(v51[0]) = -86;                            // report[0] = 0xAA
*(_OWORD *)((char *)v51 + 1)     = data[0..15];  // report[1..16]
*(_OWORD *)((char *)&v51[2] + 1) = data[16..31]; // report[17..32]
*(_OWORD *)((char *)&v51[4] + 1) = data[32..47]; // report[33..48]
*(_OWORD *)&v51[6]               = data[47..62]; // report[48..63]
__write_chk(fd_hidg0, v51, 64, 64);
```

⇒ **`report[0] = 0xAA`，`report[1+i] = data[i]`（i = 0..62）**

| USB report 偏移 | 来源           | 含义                         |
| --------------- | -------------- | ---------------------------- |
| `[0]`           | 常量           | `0xAA`                       |
| `[1]`           | `data[0]`      | 头/连接态（type 位所在）     |
| `[2..17]`       | `data[1..16]`  | 姿态四元数                   |
| `[18..25]`      | `data[17..24]` | 位置                         |
| `[26..29]`      | `data[25..28]` | float                        |
| `[30..31]`      | `data[29..30]` | i16                          |
| `[32..46]`      | `data[31..45]` | 8× i16（速度/加速度/角速度） |
| `[47]`          | `data[46]`     | —                            |
| `[48]`          | `data[47]`     | —                            |
| **`[49]`**      | `data[48]`     | **键值字高字节**             |
| **`[50]`**      | `data[49]`     | **键值字低字节**             |
| **`[51]`**      | `data[50]`     | 摇杆 X（中位 128）           |
| **`[52]`**      | `data[51]`     | 摇杆 Y（中位 128）           |
| **`[53]`**      | `data[52]`     | 扳机模拟量                   |
| **`[54]`**      | `data[53]`     | grip 模拟量                  |
| `[55..62]`      | `data[54..61]` | 时间戳                       |
| `[63]`          | `data[62]`     | lens separation              |

> 日志串 `Controller button state [%d,%d]` 打的是 `v190[16], v190[17]` —— 看着像「两只手」，
> 其实是**同一个 16 位键值字的两个字节**。

## 键值字位定义（抓包实测，与驱动映射代码一致）

16 位键值字：**低字节 = `report[50]`，高字节 = `report[49]`**。

| 位                            | 含义                   | 实测                                       |
| ----------------------------- | ---------------------- | ------------------------------------------ |
| bit0                          | A/X 按下               | ✅ `report[50] = 0x01`                     |
| bit2                          | B/Y 按下               | ✅ `report[50] = 0x04`                     |
| bit4                          | 摇杆按下               | ✅ `report[50] = 0x10`                     |
| bit6                          | 扳机按下（数字位）     | ✅ `report[50] = 0x40`，仅在拉扳机窗口出现 |
| bit12                         | system（左）           | ✅ `report[49] = 0x10`                     |
| bit13                         | application menu（右） | ✅ `report[49] = 0x20`                     |
| **bit1 / bit3 / bit5 / bit7** | **空闲（头显从不写）** | ❌ → **本项目用来承载电容触摸**            |
| bit8–11 / bit14 / bit15       | 空闲                   | —                                          |

> ⚠️ 早期笔记把 bit6 判为「扳机电容触摸」是**错的** —— 它与扳机按下严格同步。

## 抓包方法（不需要 USBPcap）

用驱动同款 `hidapi.dll`（`driver\bin\win64\hidapi.dll`）+ ctypes：

- `artifacts/hidcap.py`：用法 `uv run python hidcap.py <秒数> <out.log>`
- 输出格式：`t<TAB>iface<TAB>len<TAB>hex`，首行 `# <本地时间ISO> secs=...` ← **时间基准**
- 空闲时 1 Hz、内容不变的 keepalive；串流时 ~1000 Hz

**HID 输入报文会广播给所有已打开的句柄**，所以驱动在跑的同时也能读。

若驱动改成独占打开，退化为 USBPcap（需重启一次生成 `\\.\USBPcap1`；
Wireshark 的 extcap 集成在本机不通，直接用 `USBPcapCMD.exe -d \\.\USBPcap1 -o x.pcap -A -s 512`）。

## 时间对齐

`vrserver.txt` 的墙钟时间戳 ↔ 抓包相对时间：

```
抓包首行 # 2026-10-03T20:33:50
vrserver 20:35:07.937  ⇒  抓包 t = 77.937
```
